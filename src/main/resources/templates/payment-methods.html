What a fixture owns, what the provider owns, and where this list comes from

A seeded payment method is a fixture: the simulator owns its identity, its owner, its alias and the card facts, and the provider owns the ids it is driven by. Beside each provider-native id this screen prints what the provider holds under it right now, so an owner id shared by several fixtures names one object on every row that carries it, and a method a client has detached over the provider's own route reads as ended here without leaving the list. This screen shows exactly what returns and offers exactly what that control API can do, so a screen never becomes a second source of truth about what a test run holds.

Seed a payment method

This form asks for the last four digits, the brand, the expiry and the funding, and for no card number and no verification code. The simulator stores neither anywhere, so a seeded card has neither to leak, and a decline is chosen by a scenario rule rather than by a card number.
