What is in this document, and what is deliberately not

This is the setup this test run holds, as a document: the vocabulary it was written against, the run it came from, the clock it is pinned to, the accounts and their plainly declared fields, the webhook targets, the route aliases, the settings, the payment-method fixtures and the scenario rules. Copy it to keep a reproducible setup beside a test, and paste it back below into this run or another one.

No value this provider declares secret is in it. Each account names the secret fields it leaves out, and an import is given those separately in the box below. A run whose rules narrow on a request header cannot be exported whole, because a header value is supplied verbatim by whoever wrote the rule and is the one part of a rule that can hold a credential.

Take a bundle back

What a dry run says, what is created, updated or skipped, and where a secret goes

A dry run and a real import answer the same report, and differ only in whether it was applied, so what a dry run says is what an import does. Configuration is created where the target run holds no account by that label and updated where it does; a fixture whose alias the run already holds is skipped; scenario rules are always created, because a document carries what a rule is and never what it was called, so taking the same bundle back twice leaves two sets of rules.

The secrets box is never filled back in by this screen, whether the import was applied or refused. What is typed there is written to the provider's own account configuration and to nowhere else.
