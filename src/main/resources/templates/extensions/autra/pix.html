Hand out a Pix payload

A Pix is a Brazilian instant transfer. The payer copies a line of text — the payload a bank app draws as a QR code — into their own bank app and pays from there, so there is no page to send them to and no card anywhere in it. Autra answers this call with that payload, which it names qrCode, and with the moment it stops working, which it names expiresAt. This screen prints the payload as text and draws no picture of it.

Autra publishes no way to ask it how a Pix is going — "Sem endpoint público de status", no public status endpoint — so what moves a Pix here is the payer step further down this screen, and what tells a merchant about it is the callback autra sends.

This test run configures no autra account, and a Pix is collected for a merchant. Add one on the Configuration screen before you start one here.
Autra publishes no minimum, no maximum and no limit on decimal places for a Pix, and types this as a number in units of the currency and never in cents.
Autra types this as a plain string and never as an enumeration, writes BRL in every example and instructs "Use BRL" in prose.
Autra publishes this as optional and says where it shows up: "Aparece no app do banco do pagador" — it appears in the payer's bank app.
Autra denies this is an idempotency key for a Pix — "a API não bloqueia 2 Pix com mesmo orderId hoje", the API does not stop two Pix sharing one orderId today — so two checkouts under one reference produce two payloads here, because that is what autra does.
What this screen sends, and what it does not travel through

This form starts a Pix the same way a client application would, on the account picked above, and sends the way of starting as POST /v1/acquiring/pix/checkout, which is how autra spells it on its own wire. The documentId and the acquiring session token autra requires are filled in from the account, and the checks autra's own route makes on a client's credential are not made on a Pix an operator started: the audit trail records it as started from this screen and never as one a client sent.
