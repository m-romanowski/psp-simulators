What the account filter matches, and why there is no order id and no customer

The account is the identity a tester configured, such as merchant-1, and never a credential: the fields that authenticate an account stay redacted where they are stored, and the trail carries the identity beside them. A row names one where the simulator knew which account acted — a provider exchange whose credentials matched exactly one account of this run, a callback posted to that account's target, a payment a tester started as it — and names none on an exchange whose credentials matched no account or several, and on a row written before the trail carried the column at all. Order id and customer are still not offered. The stored row has no column for either: an order id is each provider's own name for the object this trail already filters by as the id the provider answered with, and the providers of this build do not agree that they have a customer at all, so a core column for either would answer nothing and look like an empty trail.
