What an empty field narrows, and how a story's steps fire

A field left empty narrows nothing. A rule that names no operation is consulted for every call of this provider, and one that names a story is a step of it: it fires only while that story stands in whenState, and leaves it in thenState. A step that names no whenState fires whatever state the story stands in, and one that names no thenState moves it nowhere.

How the engine breaks a tie, and why the values are not printed here

The engine consults the rules a request matches and takes the highest priority, then the most specific, then the newest. A rule narrowed by a story state counts one more towards how narrow it is than the same rule without one. Written order is a column rather than a timestamp because a pinned clock gives every rule written in one moment the same written time.

A rule's match conditions are values a reader typed, and they stay off this page until that reader opens one rule and asks for them. The field names and how many values each carries are always here.

Five things the Scenarios screen is asked for, and why each is absent

These are asked of the Scenarios screen and are absent rather than empty, because the scenario model cannot express them today.

edit a rule
A written rule is not rewritten anywhere in this simulator. Rewriting one as a delete and a fresh write would hand it a new scenario id and a new arrival, which would break the audit rows that name the old id and could change which rule wins a tie. Delete it and write the rule you meant.
disable a rule
A rule is written or absent; nothing holds a disabled rule that could be brought back.
a delayed terminal state
No action writes a normalized status: a status is derived from the native status and the operation list. A call answered one way and then another is written as a story of two steps, and a delay is the transport fault DELAYED_RESPONSE, which holds an already-rendered response rather than moving an object later.
a webhook or callback delivery plan
A scenario action can hold back, repeat or drop one delivery, and never reorders the queue. Which events are sent, the address they go to and the retry policy come from the webhook control route and are shown on Webhooks.
the newest calls a rule decided
The audit trail is read oldest first and pages forward only, so a rule that decided more calls than one page holds shows the newest of that page and not the newest of the trail.
