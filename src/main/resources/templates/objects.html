Where these three answers come from, and what is reachable nowhere

Capturable and refundable are the provider's answer and not arithmetic over the list below: a provider can hold money the sums call available and still refuse to move it. Both are answers about this object alone, and a provider may report an object at a status its own next operation belongs to another object for: what this one is tied to is listed further down.

A step still moves it counts the three things this screen can do that change this payment: an operation this provider offers on it, a follow-up this provider names on it, and the payer's own step where one is still to be taken. Sending a callback is none of them, because a callback reports this payment to the merchant and moves nothing, so it is offered whatever this answer says.

Capture, cancel and refund, wherever this provider offers them, are that provider's own operations, run below the screen exactly as its own route runs them; the panel underneath says which of the three it offers and what it publishes in place of the ones it does not. Forcing a status and triggering a reconciliation response are reachable nowhere: no control-API route, no provider route and no service of this simulator performs either, so this screen does not offer them either.
